## PPDB Payment Confirmation Status Audit - SPMB-2026-71980

### The Problem
Applicant SPMB-2026-71980 confirmed payment in admin panel shows:
- ✅ Admin detail page: "Pembayaran telah dikonfirmasi" (green checkmark)
- ❌ Cek-kode page: "Pembayaran Sedang Diverifikasi" (amber, pending)

### Root Cause Analysis
The `status` column in ppdb_applications table wasn't being persisted when admin confirmed payment, even though `status_history` JSON was updated correctly.

### Fixes Applied

#### 1. HTTP Cache Busting (PpdbAuthController)
**Files:**
- `app/Http/Controllers/PpdbAuthController.php` lines 152-162 and 202-214

Added headers to prevent browser caching:
```php
Cache-Control: no-cache, no-store, max-age=0, must-revalidate
Pragma: no-cache
Expires: Thu, 01 Jan 1970 00:00:00 GMT
```

#### 2. Payment Status Save Verification (Route handlers)
**Files:**
- `routes/web.php` line 349-390 (SMK payment route)
- `app/Http/Controllers/Admin/AdminPpdbApplicantsController.php` (all schools)

**Logic:**
```
1. Set $applicant->status = 'payment_confirmed'
2. Call $applicant->save()
3. Refresh() the applicant from database
4. Verify status was actually saved
5. If NOT saved, use raw SQL UPDATE as fallback
6. Log everything for debugging
```

#### 3. Debug Logging
All payment confirmation routes now log:
- applicant_id
- application_id  
- status_before (original value)
- status_after_save (value after ORM save)
- status_after_refresh (value after refresh from DB)
- school_id
